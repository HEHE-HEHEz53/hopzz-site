# 03 环境与代码：装好 Arduino IDE，读懂每一段代码

这一篇分两半：

- **前半**：装软件、装开发板包、装库、上传第一个程序。
- **后半**：把 `code/` 里每个 `.ino` 拆开讲，告诉你“这段在干嘛、为什么这么写”。

不要跳过前半直接看代码。Arduino 的环境没装对，代码再对也上传不进去。

---

## 零、先避开一个新手必踩的坑：不要直接打开整个 `code` 文件夹

Arduino IDE 的规则是：**一个文件夹 = 一个项目（Sketch），文件夹里所有 `.ino` 会合并成一个程序编译。**

`code/` 里有 5 个 `.ino`，每个都有 `setup()` 和 `loop()`。如果你直接打开整个文件夹，IDE 会把它们拼在一起，然后报：

```text
multiple definition of `setup()'
multiple definition of `loop()'
```

**这不是代码错了，是打开方式错了。**

正确做法（二选一）：

1. **新建 Sketch，粘贴**：`文件 → 新建 Sketch`，另存为 `01_blink`，把 `code/01_blink.ino` 的内容全选复制进去。
2. **单文件独立文件夹**：新建文件夹 `01_blink`，只把 `01_blink.ino` 复制进去，再用 IDE 打开它。

详细说明在 [code/README.md](code/README.md)。**每做一个实验，只保留一个 `.ino` 在项目文件夹里。**

## 一、安装 Arduino IDE 2.x

### 1.1 下载

打开 Arduino 官网的软件页面：

```text
https://www.arduino.cc/en/software
```

下载 **Arduino IDE 2.x** 的 Windows 版本（一般选 “Windows Win 10 and newer, 64 bits”）。不要用很老的 1.8.x 教程照搬，2.x 的界面和 1.8 不一样，但核心操作一样。

安装时一路下一步即可。如果安装程序问要不要装 USB 驱动，选**是/允许**。装完打开 IDE，不需要注册账号。

> 你的电脑是 Windows 的话，下面按 Windows 讲；macOS 和 Linux 的菜单名基本一样，只是串口名字不同（Linux 是 `/dev/ttyUSB0` 或 `/dev/ttyACM0`，macOS 是 `/dev/cu.usbserial-*`）。

### 1.2 插上板子，确认电脑能看见它

用**能传数据**的 USB 线把 ESP32 插到电脑：

- 板子上的电源灯应该亮。
- Windows 会“叮”一声，右下角提示安装设备。
- 打开**设备管理器**（开始菜单右键 → 设备管理器），展开 **端口（COM 和 LPT）**，应该能看到类似：

```text
Silicon Labs CP210x USB to UART Bridge (COM3)
```

或者：

```text
USB-SERIAL CH340 (COM4)
```

`COM3`、`COM4` 这个编号记住，后面选端口要用。**你的编号可能不一样，以你电脑显示的为准。**

如果看到的是：

- **“未知设备”/黄色感叹号**：驱动没装好。
- **“USB 串行设备”但没有 COM 口**：还是驱动问题。
- **什么都没有**：先怀疑 USB 线只能充电，换一条数据线；再怀疑 USB 口/板子。

驱动怎么装：

| 板子上的芯片 | 去哪个官方找驱动 | 说明 |
|---|---|---|
| CP2102 / CP2104 | Silicon Labs 的 CP210x USB to UART Bridge VCP Drivers | 下载对应 Windows 版本，安装后重新插拔 |
| CH340 / CH341 | 沁恒（WCH）官网的 CH341SER 驱动 | 安装后重新插拔 |

不要从不明来源的“驱动大全”网站下 exe。装完驱动重新插拔板子，设备管理器里应出现 COM 口。还不行就去看 [05-常见问题.md](05-常见问题.md) 第一条。

## 二、给 Arduino IDE 加 ESP32 开发板包

Arduino IDE 默认只认识 Arduino 自己的板子。ESP32 是乐鑫（Espressif）的芯片，要额外加一个**开发板包**（board package）。

### 2.1 填开发板管理器地址

1. 打开 `文件 → 首选项`（File → Preferences）。
2. 找到 **“附加开发板管理器网址”**（Additional Boards Manager URLs）。
3. 在输入框里加这一行（如果里面已有别的网址，用逗号或换行隔开，不要覆盖）：

```text
https://espressif.github.io/arduino-esp32/package_esp32_index.json
```

4. 点“确定”。

这个地址是乐鑫官方的 ESP32 Arduino 包索引。**不要**从第三方网盘下“ESP32 离线包”，版本和库经常对不上。

### 2.2 安装 esp32 开发板包

1. 打开 `工具 → 开发板 → 开发板管理器`（Tools → Board → Boards Manager）。
2. 搜索框输入 `esp32`。
3. 找到 **“esp32 by Espressif Systems”**，点“安装”。
4. 等它下载完。这个包比较大（几百 MB），网络慢的话要几分钟，进度条不动别急着关。

安装完成后，`工具 → 开发板` 里会多出 `esp32` 这一组。

> 版本怎么选：列表里会显示版本号。**本教程的代码用的是 WiFi/HTTPClient/DHT 这些常用 API，2.0.x 和 3.x 都能用。** 新手不必追最新，选列表里标记为稳定的版本即可；如果某个新版和库不兼容，退回 2.0.x 的稳定版（例如 2.0.17）通常能解决。

### 2.3 选板子和端口

1. `工具 → 开发板 → esp32 → ESP32 Dev Module`。
   - 你买的是 ESP32-WROOM-32 DevKit V1，就选这个。
   - 不要选 ESP32-S3、ESP32-C3，除非你买的确实是那个型号。
2. `工具 → 端口`，选设备管理器里看到的 COM 口（例如 COM3）。
3. 其他设置先保持默认：
   - Upload Speed：`921600`（上传失败就降到 `115200`）
   - Flash Frequency：`80MHz`
   - Flash Size：`4MB`
   - Partition Scheme：`Default 4MB with spiffs`

> 板子型号和端口，是上传失败最常见的原因。每次换 USB 口、换板子，都回来检查这两项。

## 三、安装库

**开发板包**和**库**是两回事：

- 开发板包：让 IDE 认识 ESP32，并提供 `WiFi.h`、`HTTPClient.h` 这些底层能力。
- 库：某个具体传感器的驱动，比如 DHT22 的 `DHT.h`。

### 3.1 DHT22 需要两个库

打开 `工具 → 管理库`（Tools → Manage Libraries），搜索并安装：

1. 搜索 `DHT sensor library`，作者 **Adafruit**，点安装。
2. 安装时通常会提示依赖 **Adafruit Unified Sensor**，点“全部安装”/“Install all”。

装完后，`文件 → 示例 → DHT sensor library` 里应该能看到示例，说明库装好了。

### 3.2 可选库

| 你要用的硬件 | 库名（Library Manager 里搜） | 作者 |
|---|---|---|
| SHT30 | `Adafruit SHT31`（依赖 `Adafruit BusIO`） | Adafruit |
| OLED SSD1306 | `Adafruit SSD1306` + `Adafruit GFX Library` | Adafruit |
| BH1750 | `BH1750`（选常见维护版本） | Christopher Laws 等 |
| JSON（本教程不需要） | `ArduinoJson` | Benoit Blanchon |

**本教程的 3 个核心代码只依赖 DHT 库 + ESP32 开发板包，不依赖 ArduinoJson。** 原因在后面讲 03 代码时会说。

> 如果编译报 `DHT.h: No such file or directory`，就是 DHT 库没装，或者装到了错误的 IDE/用户目录。回到 Library Manager 重装一次，装完重启 IDE。

## 四、上传第一个程序：01_blink

### 4.1 建项目

按第零节的方法：

1. `文件 → 新建 Sketch`。
2. `文件 → 另存为`，名字写 `01_blink`。
3. 把 [code/01_blink.ino](code/01_blink.ino) 的全部内容复制进去。
4. 点左上角的**验证**按钮（一个对勾图标），先编译。
5. 编译通过后，点**上传**按钮（向右的箭头图标）。

### 4.2 上传时发生了什么

IDE 会先编译，然后通过 USB 转串口芯片把程序写进 ESP32。上传时你会看到：

```text
Connecting........_____.....
Chip is ESP32-D0WDQ6 (revision 1)
...
Hash of data verified.
Leaving...
Hard resetting via RTS pin...
```

看到 `Hard resetting` 就成功了，板子会自动复位运行。

### 4.3 如果卡在 “Connecting...”

有些板子的自动复位电路不灵，需要手动进下载模式：

1. 按住板子上的 **BOOT** 键不放。
2. 点 IDE 的上传按钮。
3. 看到 `Connecting...` 后，松开 BOOT。
4. 上传完成后按一下 **EN**（复位）键，程序开始运行。

如果还是失败：

- 换 USB 口/换数据线；
- 上传速度降到 `115200`；
- 关掉串口监视器（Windows 上 COM 口被占用时无法上传）；
- 确认板子选的是 `ESP32 Dev Module`，端口是刚看到的 COM 口。

### 4.4 看串口输出

1. 点右上角的**串口监视器**图标。
2. 右下角波特率选 **115200**。
3. 按一下板子的 **EN** 键复位。

你应该看到：

```text
=================================
ESP32 blink start
LED pin: GPIO2
=================================
LED ON
LED OFF
LED ON
...
```

同时板载 LED 每秒闪一次。

**灯不亮但串口有输出？** 说明程序在跑，只是 LED 的接法不同：

- 把代码里的 `LED_ON` 改成 `LOW`、`LED_OFF` 改成 `HIGH` 再试；
- 或者查你板子的 LED 到底接哪个 GPIO，改 `LED_PIN`。

**串口全是乱码？** 波特率不是 115200，或者你选错了端口。看 [05-常见问题.md](05-常见问题.md)。

## 五、逐个讲代码

下面按文件讲。代码文件本身已经写了逐行中文注释，这里讲**整体思路和关键行为**，帮你把“照着抄”变成“看得懂”。

### 5.1 `01_blink.ino`：最小验证

```cpp
#define LED_PIN 2
#define LED_ON HIGH
#define LED_OFF LOW
#define BLINK_INTERVAL_MS 1000UL
```

- `#define` 是**宏定义**，在编译前把名字替换成后面的值。把常量集中放在文件顶部，是嵌入式代码的好习惯：以后改引脚、改间隔，只改一处。
- `2` 是 GPIO 编号，不是“第 2 根针”。多数 DevKit V1 的板载 LED 接 GPIO2。
- `HIGH` / `LOW` 是 Arduino 对 1 / 0 的别名。
- `1000UL` 的 `UL` 表示“无符号长整型”（unsigned long），`delay()` 接受这个类型，写 `1000` 也能编译，但加上 `UL` 更明确。

```cpp
void setup() {
  Serial.begin(115200);
  pinMode(LED_PIN, OUTPUT);
}
```

- `setup()`：上电后**只运行一次**。适合做初始化：开串口、设引脚模式、连 WiFi。
- `Serial.begin(115200)`：打开串口，波特率 115200。**串口监视器也要选 115200**，两边必须一致。
- `pinMode(LED_PIN, OUTPUT)`：把 GPIO2 设成输出。只有输出模式，`digitalWrite` 才能驱动 LED。

```cpp
void loop() {
  digitalWrite(LED_PIN, LED_ON);
  delay(1000);
  digitalWrite(LED_PIN, LED_OFF);
  delay(1000);
}
```

- `loop()`：`setup()` 之后**反复运行**，直到断电。Arduino 框架在背后帮你写了 `main()`，它调用一次 `setup()`，然后无限调用 `loop()`。
- `digitalWrite(pin, HIGH/LOW)`：让引脚输出高/低电平。
- `delay(ms)`：阻塞等待，单位毫秒。**`delay` 期间板子什么别的事都做不了**。点灯阶段无所谓，后面做联网/多任务时要注意。

### 5.2 `02_read_sensor.ino`：读 DHT22

```cpp
#include <DHT.h>
#define DHT_PIN 4
#define DHT_TYPE DHT22
DHT dht(DHT_PIN, DHT_TYPE);
```

- `#include <DHT.h>`：把 DHT 库引进来。没有这行，编译器不认识 `DHT`。
- `DHT dht(DHT_PIN, DHT_TYPE)`：创建一个 DHT 对象，告诉库“数据脚是 GPIO4，型号是 DHT22”。
- 这是**全局对象**，`setup()` 和 `loop()` 都能用。

```cpp
void setup() {
  Serial.begin(115200);
  dht.begin();
  delay(2000);
}
```

- `dht.begin()`：初始化传感器引脚和内部状态。
- `delay(2000)`：DHT22 上电后需要时间稳定，等 2 秒再读。

```cpp
float humidity = dht.readHumidity();
float temperature = dht.readTemperature();
if (isnan(humidity) || isnan(temperature)) {
  Serial.println("读取失败...");
  return;
}
```

- `float`：带小数的浮点数。温湿度不是整数，所以用 `float`。
- `readHumidity()` 返回 %RH；`readTemperature()` 默认摄氏度，写 `readTemperature(true)` 返回华氏度。
- `isnan()`：判断是不是 `NaN`（Not a Number）。DHT 库读失败时返回 `NaN`，如果不判断，串口会打印 `nan`，而且发到服务器会变成非法 JSON。
- `return`：直接结束这一次 `loop()`，跳过后面的打印，等下一次再试。

```cpp
delay(2000);
```

- DHT22 两次采样至少隔 2 秒。**读太快会一直 NaN**，这不是传感器坏了。

> 为什么不用 `while (true)` 一直读？因为那样会刷屏，而且 DHT22 也受不了。固定间隔更接近真实项目。

### 5.3 `02b_read_sht30.ino`：可选，I2C 传感器

```cpp
#include <Wire.h>
#include <Adafruit_SHT31.h>
Wire.begin(21, 22);
if (!sht30.begin(0x44)) { ... }
```

- `Wire.h` 是 ESP32 的 I2C 库。I2C 只需要两根线：SDA（数据）和 SCL（时钟）。
- `Wire.begin(21, 22)`：告诉 ESP32 用 GPIO21 当 SDA、GPIO22 当 SCL。
- `sht30.begin(0x44)`：按 I2C 地址 0x44 初始化。读不到就试 0x45。
- `while (true) { delay(1000); }`：初始化失败就停在这里，串口一直提示。测试阶段这样可以，正式项目里应该重试而不是死机。

### 5.4 `02c_relay_test.ino`：继电器测试

```cpp
#define RELAY_PIN 26
#define RELAY_ACTIVE_LOW 1
```

- `RELAY_ACTIVE_LOW 1` 表示**低电平触发**：GPIO 输出 LOW 时继电器吸合。
- 如果你的模块是**高电平触发**，改成 `0`。

```cpp
void relayOn() {
  if (RELAY_ACTIVE_LOW) digitalWrite(RELAY_PIN, LOW);
  else digitalWrite(RELAY_PIN, HIGH);
}
```

- 把“吸合/断开”的细节封装成函数，`loop()` 里只写 `relayOn()` / `relayOff()`，可读性好。
- 吸合/断开之间留 3 秒，你能清楚听到“嗒”的声音。

**安全**：这个测试只接 5V/12V 小负载。不要接 220V。

### 5.5 `03_post_to_server.ino`：连 WiFi + HTTPS 上报

这是本教程的核心。分成几块看。

#### 顶部常量

```cpp
#define WIFI_SSID "把你的WiFi名称填在这里"
#define WIFI_PASSWORD "把你的WiFi密码填在这里"
#define DEVICE_ID "esp32-01"
#define DEVICE_TOKEN "把服务器给你的设备令牌填在这里"
#define SERVER_HOST "hopzz.top"
#define TELEMETRY_PATH "/api/telemetry"
#define REPORT_INTERVAL_MS 30000UL
```

| 常量 | 你要不要改 | 说明 |
|---|---|---|
| `WIFI_SSID` | **要** | 2.4GHz WiFi 名称 |
| `WIFI_PASSWORD` | **要** | WiFi 密码 |
| `DEVICE_ID` | 一般不用 | 设备标识，契约里是 `esp32-01`；多台设备要各不相同 |
| `DEVICE_TOKEN` | **要** | 服务端生成的设备令牌，不是 WiFi 密码 |
| `SERVER_HOST` | 不用 | 用域名 `hopzz.top`，不要改成 IP |
| `TELEMETRY_PATH` | 不用 | 契约规定的路径 |
| `REPORT_INTERVAL_MS` | 可改 | 上报间隔，默认 30 秒 |

**为什么用 `#define` 放顶部？** 因为新手最容易把 WiFi 密码、令牌散落在代码中间。集中放顶部，改的时候不会漏，也不容易把令牌提交到公开仓库。

#### 引入库

```cpp
#include <WiFi.h>
#include <WiFiClientSecure.h>
#include <HTTPClient.h>
#include <DHT.h>
#include <stdio.h>
```

- `WiFi.h`：连 WiFi。
- `WiFiClientSecure.h`：提供支持 TLS（HTTPS 的加密层）的客户端。
- `HTTPClient.h`：帮你拼 HTTP 请求、发 POST、读状态码。
- `DHT.h`：温湿度传感器驱动。
- `stdio.h`：提供 `snprintf`，用来拼 JSON。
- 前三个是 ESP32 开发板包自带的，不用在 Library Manager 里装。

#### `connectWiFi()`

```cpp
WiFi.mode(WIFI_STA);
WiFi.setAutoReconnect(true);
WiFi.persistent(false);
WiFi.setSleep(false);
WiFi.begin(WIFI_SSID, WIFI_PASSWORD);
```

- `WIFI_STA`：ESP32 作为“客户端”去连路由器，不是自己开热点。
- `setAutoReconnect(true)`：断线后底层自动重连。
- `persistent(false)`：不把 WiFi 信息反复写进 flash，保护 flash。
- `setSleep(false)`：关闭省电模式，减少“请求发到一半卡住”的概率，代价是功耗略高。
- `WiFi.begin()`：开始连接。

```cpp
while (WiFi.status() != WL_CONNECTED && (millis() - startMs) < 20000) {
  delay(500);
  Serial.print(".");
}
```

- `millis()` 返回上电后经过的毫秒数。用 `millis() - startMs` 做超时，不用 `delay(20000)` 干等。
- 20 秒还没连上就放弃，`loop()` 后面还会再试。

#### `readSensor()`

```cpp
bool readSensor(float &temperature, float &humidity) {
  humidity = dht.readHumidity();
  temperature = dht.readTemperature();
  if (isnan(temperature) || isnan(humidity)) return false;
  return true;
}
```

- `float &temperature` 是**引用参数**：函数内部改它，外面的变量也会变。这样函数可以返回“成功/失败”，同时带回两个读数。
- 返回 `bool`：成功 `true`，失败 `false`。调用方根据返回值决定要不要发。

#### `postTelemetry()`：拼 JSON、发 POST

```cpp
char payload[160];
int len = snprintf(payload, sizeof(payload),
  "{\"device_id\":\"%s\",\"temperature\":%.1f,\"humidity\":%.1f}",
  DEVICE_ID, temperature, humidity);
```

- `snprintf` 把格式化的 JSON 写进 `payload` 字符数组。
- `\"` 是 JSON 里的双引号转义；`%.1f` 表示保留 1 位小数的浮点数。
- **数字不要加引号**：`"temperature":26.5` 是数字，`"temperature":"26.5"` 是字符串，服务端可能按数字校验。
- 缓冲区 160 字节够放这个固定格式；如果以后加字段，要同步加大。

**为什么不用 ArduinoJson？** 这个 JSON 只有 3 个字段、格式固定，用 `snprintf` 更轻，不用多装一个库。等你以后要解析复杂响应、字段很多，再上 ArduinoJson。

```cpp
WiFiClientSecure client;
client.setInsecure();
HTTPClient https;
if (!https.begin(client, SERVER_HOST, TELEMETRY_PORT, TELEMETRY_PATH, true)) {
  return -2;
}
https.addHeader("Content-Type", "application/json");
https.addHeader("X-Device-Token", DEVICE_TOKEN);
int statusCode = https.POST(String(payload));
String response = https.getString();
https.end();
```

- `WiFiClientSecure` 是“支持 HTTPS 的客户端”。普通 `WiFiClient` 只能跑 HTTP。
- `client.setInsecure()`：**临时**跳过证书校验。这样 ESP32 时间不对也能连上。**生产环境要换掉**，详见 [04-连上服务器.md](04-连上服务器.md)。
- `https.begin(...)`：告诉 HTTPClient 目标主机、端口、路径，并明确这是 HTTPS。
- `setTimeout()` 管读取超时，`setConnectTimeout()` 管建连/握手超时；TLS 握手比普通 HTTP 慢，所以都设成 10 秒。
- `addHeader`：契约要求的两个请求头。`X-Device-Token` 少了就是 401。
- `POST`：发请求，返回值是 HTTP 状态码。`200` 成功，`401` 令牌错，`422` 字段缺失/格式错。
- `getString()`：读服务器返回的响应体，打印出来方便排查。
- `end()`：结束请求，释放连接。

#### `sendWithRetry()`：什么时候重试，什么时候不重试

```cpp
if (statusCode == 200) return true;
if (statusCode == 401) return false;  // 令牌错，重试没用
if (statusCode == 422) return false;  // 数据错，重试没用
// 网络错误、5xx、408、429：1s、2s、4s 退避后重试
```

- `200`：成功。
- `401`：设备令牌不对。再试 100 次也还是 401，应该去改 `DEVICE_TOKEN`。
- `422`：字段缺失或格式不对。重试也不会变对，应该去检查 JSON。
- 其他 `4xx`（400/403/404/405 等）：URL、权限、方法有问题，不重试。
- 网络错误（HTTPClient 返回负数）、`5xx`、`408`、`429`：临时问题，值得退避重试。
- `3xx`：重定向。当前代码不跟随，检查 URL 是否写错（例如该用 `hopzz.top` 却写了 `www`）。
- 退避（backoff）：等 1 秒、2 秒、4 秒，避免把服务器打爆。

#### `timeToReport()`

```cpp
static bool firstRun = true;
if (firstRun || (now - lastReportMs >= REPORT_INTERVAL_MS)) { ... }
```

- 第一次调用返回 `true`，让设备上电后**立刻**报一次，不用干等 30 秒。
- `static` 变量只初始化一次，函数返回后值还在。
- `millis()` 是无符号长整型，运行约 49 天后会回绕；用 `now - lastReportMs` 的差值判断，回绕时也能正确工作。

#### `setup()` 和 `loop()`

- `setup()`：开串口、初始化 DHT、等 2 秒、连 WiFi。
- `loop()`：到点才上报；WiFi 断了重连；传感器 NaN 就跳过；一切正常就 `sendWithRetry()`。

**为什么 `loop()` 里用 `delay(100)` 而不是空转？** 空转会占满 CPU、增加功耗。加 100ms 让出时间，简单又够用。真正复杂的项目会用非阻塞定时器，这里先不引入。

## 六、编译/上传错误速查

| 现象 | 最可能的原因 | 怎么修 |
|---|---|---|
| `DHT.h: No such file or directory` | DHT 库没装 | Library Manager 装 `DHT sensor library` + `Adafruit Unified Sensor`，重启 IDE |
| `Board esp32:esp32:esp32 not found` | ESP32 开发板包没装 | 按第二节加 URL，装 `esp32 by Espressif Systems` |
| `Failed to connect to ESP32` | 没进下载模式/端口错/线不对 | 按住 BOOT 再点上传；换数据线；端口选对；速度降到 115200 |
| `multiple definition of setup()` | 一个文件夹里放了多个 `.ino` | 按第零节，一次只留一个 `.ino` |
| `Sketch too big` | 分区/板子选错 | 选 `ESP32 Dev Module`，分区 `Default 4MB with spiffs` |
| 串口乱码 | 波特率不一致 | 串口监视器选 115200；还乱就换端口/换线 |
| `Port is busy` / 打不开串口 | 串口监视器占着 COM 口 | 先关串口监视器再上传 |
| 上传成功但串口没输出 | 波特率/端口/复位 | 按 EN 复位；确认 115200；确认选的是板子的 COM 口 |
| 板子反复重启，串口显示 `Brownout` | 供电不足 | 换 5V 1A 电源/换粗线；继电器单独供电；见 05 |
| 温湿度一直是 `NaN` | 接线/上拉/型号 | 查 DHT22 三根线、上拉电阻、`DHT_TYPE`；见 05 |
